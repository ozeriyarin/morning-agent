# Interview tips

One Hebrew tip per line; `- [ ]` is unused, a used line becomes `- [x] YYYY-MM-DD <tip>`. When
every tip is used the queue starts again from the first one.

- [ ] בראיון התנהגותי ענו במבנה STAR: מצב, משימה, פעולה, תוצאה, ותנו לתוצאה מספר.
- [ ] פתחו בעוזר שרץ בפרודקשן: מה הוא עושה, למי, ומה השתנה בזכותו.
- [ ] agent loop במשפט: המודל בוחר פעולה, הקוד מריץ את הכלי, והתוצאה חוזרת למודל עד שהמשימה נגמרת.
- [ ] RAG במשפט: מאחזרים קטעים רלוונטיים מהמסמכים ומצרפים אותם לפרומפט, כדי שהמודל יענה מתוך המידע.
- [ ] tool calling במשפט: המודל מחזיר בקשה מובנית לפונקציה עם ארגומנטים, והקוד מריץ אותה ומחזיר תוצאה.
- [ ] הציגו את תהליך הפיתוח האג'נטי שלכם: spec, סוכן מפתח, סוכן בודק, וטסטים שרצים לפני כל commit.
- [ ] בשאלת system design התחילו מדרישות ועומסים (משתמשים, בקשות לשנייה, נפח נתונים) לפני הקופסאות.
- [ ] כשלא יודעים, אמרו מה כן ידוע ואיך הייתם בודקים; ניחוש בביטחון פוגע יותר משאלה טובה.
- [ ] בשאלת קוד חזרו על השאלה במילים שלכם ושאלו על קלטים קיצוניים לפני השורה הראשונה.
- [ ] הכינו סיפור על באג בפרודקשן: איך גיליתם, איך הוכחתם את הסיבה, ואיזה טסט מונע את החזרה שלו.
- [ ] בשאלה על עלויות LLM דברו על מודל לפי משימה, caching של הפרומפט והגבלת טוקנים.
- [ ] evals במשפט: סט קבוע של דוגמאות עם ציפיות שרץ על כל שינוי בפרומפט או במודל ומראה אם השתפרנו.
- [ ] בשאלת "למה אנחנו" חברו מוצר אמיתי של החברה לפרויקט שבניתם, לא משפט מהאתר.
- [ ] נגד hallucinations תנו שלוש הגנות: עיגון במקורות, פלט מובנה עם ולידציה, ובדיקת לינקים ומספרים בקוד.
- [ ] multi-tenant במשפט: כל שאילתה מסוננת לפי tenant (או RLS), ויש טסט שמוכיח שאין דליפה בין לקוחות.
- [ ] בכל תכנון מערכת ציינו trade-off אחד במפורש: על מה ויתרתם ולמה זה בסדר בשלב הזה.
- [ ] הכינו שאלה לסוף הראיון: איך הצוות מודד איכות של פיצ'רים מבוססי AI.
- [ ] structured output במשפט: נותנים למודל סכמת JSON ומוודאים את הפלט מולה לפני שמשתמשים בו.
- [ ] SSE מול WebSockets: SSE לזרם חד-כיווני מהשרת ופשוט יותר; WebSockets כשצריך תקשורת דו-כיוונית.
- [ ] "ספר על עצמך": שתי דקות, מההווה לעבר, ומסיימים בלמה התפקיד הזה הוא הצעד הבא.
- [ ] בשאלה על כישלון בחרו כישלון אמיתי והקדישו את רוב הזמן למה שלמדתם ושיניתם.
- [ ] embeddings במשפט: וקטור שמייצג משמעות של טקסט, כך שטקסטים דומים קרובים ואפשר לחפש לפי משמעות.
- [ ] בשאלת scale דברו על caching, תורים לעבודה אסינכרונית ו-pagination לפני שמוסיפים שרתים.
- [ ] הביאו את הבריף הזה כדוגמה: מודל זול להחלטות, מודל חזק לכתיבה, ורשומת עלות לכל ריצה.
- [ ] בשאלת קוד אמרו את הסיבוכיות בקול לפני שמשפרים, ואז הציעו שיפור אחד ממוקד.
- [ ] בשאלה על עבודת צוות תנו דוגמה ל-code review שבו קיבלתם הערה ושיניתם גישה.
- [ ] prompt injection במשפט: טקסט חיצוני מנסה לתת למודל הוראות, ולכן כל קלט חיצוני הוא נתונים בלבד.
- [ ] בשאלת שכר תנו טווח שבדקתם מראש ושאלו על כל החבילה, לא רק על הבסיס.
- [ ] מודל החלטות זול במשפט: בחירה סגורה מתוך רשימה קבועה, ולכן הוא זול, מהיר וקל לבדיקה.
- [ ] בסוף כל תשובה טכנית סכמו במשפט מה בחרתם ולמה; המראיין זוכר את השורה האחרונה.
